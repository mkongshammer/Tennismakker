# Validation — 2026-09-24

## Passed

- `npm test`: 179 offline server regression tests, including payment evidence/replay, wallet policy, booking checkout, roles, lighting permissions, push policy, imports and the new Resasports contract tests.
- `cd mobile && npm test`: 18 mobile component/policy tests.
- `npx next build`: optimized production build and type checking.
- `npm run test:app`: 17 isolated database/HTTP checks, including rendering all 13 club-admin and 13 superadmin pages with synthetic authenticated users.
- Created member's password accepted by the actual local login API; app-to-admin ticket accepted once and rejected on replay; player denied admin handoff; STANDARD club redirected away from CUSTOM lighting.
- Actual Prisma/SQL operations against a temporary PGlite database: member ownership, overlapping reservations, wallet debit/refund idempotency, rollback after a real ledger uniqueness failure, CSV import replay/full rollback and 51-week recurring reservations across DST.

Run the database-only subset with `npm run test:database`. For HTTP checks, first run `npx next build`, then `npm run test:app`. Test database is created in memory and served on localhost; the harness never reads a production DATABASE_URL and the local Next process receives no provider credentials. No emails, real payments, production bookings or hardware commands are issued by these tests.

## Fixed during this review

- Availability now excludes partial overlaps and bookings starting before the requested range. Expired unprepared holds do not block available slots; prepared checkout holds remain protected.
- Calendar fetch failure stops booking instead of silently using an old snapshot. Failed fetches preserve the last successful sync timestamp; uninitialized, failed or older-than-20-minute feeds advertise no slots.
- New direct Resasports snapshot/import workflow with fixed read endpoints, bounded responses, pagination checks, date conversion and explicit court mapping.

## Not established by these results

- Live Resasports response/permission compatibility: approved Nubapp API credentials were unavailable. Provider tests use contract-shaped fixtures; the actual vendor migration requires count/date/court reconciliation before confirmation.
- True parallel PostgreSQL session/locking behavior: PGlite multiplexes one underlying session.
- Stripe test-mode end-to-end or live Apple Pay/Google Pay, actual account settlements/fees, physical lights/doors, delivered APNs/FCM notifications, or installed signed native builds.
- Browser interaction/visual layout on physical iOS/Android devices. Local Chromium installation failed while downloading the browser binary. HTTP rendering checks are not visual/browser tests.

Therefore this is evidence for the listed tested flows, not a claim that every function or external integration has been verified end to end.
