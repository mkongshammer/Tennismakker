## Accessibility (axe-core 4.10, WCAG 2.2 AA rules)

Pages checked: `/`, `/courts` (results and empty), `/coaches`, `/clubs/[slug]`, `/list-your-club`, `/login`, `/signup`, `/players`, `/admin`, `/admin/bookinger`, `/profile`. Fixed during this work: low-contrast secondary text (slate/60 and slate-light), discovery results not being a real list, unnamed map markers, a focusable non-interactive origin marker, dimmed past rows in the schedule, and an unlabelled file input. Remaining: none at moderate severity or above on these pages.

## Journeys exercised with Playwright (phone viewport)

1. Guest → `/clubs/brookline-racquet-club` → "Sign in" → signs in → returned to the same club and day → taps an hour → court tile → `/checkout/<id>` → pays (mock) → `/profile?betalt=<id>` with the confirmation panel → downloads `/bookings/<id>/calendar` (valid `text/calendar`, correct UTC instants, venue address, summary).
2. `/courts?q=Denver` → no clubs → notify-me form → row written to `MarketInterest`, success message shown.
3. `/list-your-club?plan=CUSTOM` → Lights and door access → facility (state sets the time zone) → courts → account → `/club-start` checklist with the Pay step.
4. Club rule rejection (member over the active-booking cap) shows the translated reason on the club page.

## Not verified here

- Live Stripe checkout, webhooks and Connect onboarding (mock provider locally; the existing self-test and smoke workflows cover production).
- Shelly lighting and door hardware (no device access).
- Real Core Web Vitals from the field — the public origin is still `racketbuddy-us.onrender.com` and Render's cold starts dominate LCP there; that is an infrastructure decision for the owner.
- TestFlight / store builds (EAS credentials are not available in this environment).
